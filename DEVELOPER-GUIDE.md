## 1. Overview

Pocket-Mapp-Creator 0.3.0 is an Electron desktop app for drawing fantasy, sci-fi, modern and realistic maps: world maps, town maps in 3/4 view and top-down battle maps. Everything is drawn on HTML canvas in one page, with no framework and no build step for the app code.

| Item | Value |
| --- | --- |
| Runtime | Electron 44 (Chromium + Node.js), app code in plain JavaScript |
| Node.js | 24 (pinned in `.nvmrc` and the build workflow) |
| Dev dependencies | `electron`, `electron-builder` (installers), `marked` (builds the in-app user guide) |
| Runtime dependencies | None |
| Save format | `.mapp` — one JSON file, images inside as PNG data URLs |
| Installers | Windows (NSIS + portable), macOS (DMG), Linux (AppImage + .deb), built on GitHub Actions |
| Code licence | MIT, © 2026 Pocket-Designs |
| Assets | 157 original assets × 5 styles, generated by a script, CC0 |
| App icon | Custom artwork by MJO-Art; may not be altered or reused without the artist's permission |
| Contact | pocket-designs@proton.me · github.com/Pocket-Designs |

This guide is for anyone changing the code. The user guide (`docs/USER-GUIDE.md`, F1 in the app) explains how to use the app.

## 2. Getting started

You need Node.js 24 and Git. On Windows, install Node.js from nodejs.org and use Git for Windows; both work from Command Prompt.

1. Clone the repository: `git clone https://github.com/Pocket-Designs/Pocket-Mapp-Creator.git`
2. Install the dev dependencies: `npm ci` (uses `package-lock.json`, so everyone gets the same versions)
3. Run the app: `npm start`

The app runs straight from the source files. After changing a `.js`, `.css` or `.html` file in `src/`, open View → Toggle Developer Tools and press Ctrl+R with the tools focused to reload the page. Restart with `npm start` after changing `main.js` or `preload.js`.

| Command | What it does |
| --- | --- |
| `npm start` | Runs the app from source |
| `npm run assets` | Regenerates all asset SVGs and `src/asset-manifest.js` from `tools/generate-assets.js` |
| `npm run guide` | Builds `src/guide/index.html` from `docs/USER-GUIDE.md` |
| `npm run dist` | Builds installers for the current OS into `dist/` |
| `npm run dist:win` · `dist:mac` · `dist:linux` | Builds installers for one OS (each runs `guide` first) |

Installers for all three systems are normally built by GitHub Actions (section 10), so you rarely need `dist` locally.

## 3. Project layout

The app is four scripts loaded by one HTML page, plus the Electron main process. Generated files are marked; don't edit those by hand.

| Path | What it is |

| `preload.js` | The bridge: exposes `window.api` to the page through `contextBridge` |

| `src/styles.css` | All UI styling, including the responsive top bar |

| `src/asset-manifest.js` | **Generated.** List of every asset with size, kind and genre |

| `src/fonts/*.woff2` | Bundled label fonts (OFL) |
| `src/guide/` | **Generated** `index.html` plus hand-written `guide.css`, `guide.js`; the in-app user guide window |
| `docs/USER-GUIDE.md` | Source of the user guide; images in `docs/guide-images/` |
| `docs/DEVELOPER-GUIDE.md` | This guide |

| `tools/build-guide.js` | Converts the user guide Markdown to the in-app HTML |

| `LICENSE`, `ASSET-LICENSES.md` | Code licence, icon credit, asset and font licences |

Scripts load in this order in `index.html`: `asset-manifest.js`, `terrain.js`, `textures.js`, `generate.js`, `app.js`. Each later file can use what the earlier ones put on `window.MT`.

## 4. Architecture

The page never touches the disk: every file read or write goes through `window.api` to the main process.

```
┌───────────────────────────────────────────────┐
│ Renderer: src/index.html (sandboxed page)     │
│ No Node.js; strict Content-Security-Policy    │
│                                               │
│  asset-manifest.js   ASSET_MANIFEST, STYLES   │
│  window.MT libraries                          │
│    terrain.js   renderBase, generateLand,     │
│                 valueNoise, distance, rng     │        ┌──────────────────────────┐
│    textures.js  TEXTURES, textureTile         │        │ preload.js               │
│    generate.js  nameGen, voronoiCells, astar, │ window │ contextBridge exposes    │
│                 smoothLine, dungeonLayout,    │ .api.* │ window.api               │
│                 townLayout                    │ ─────▶ │ invoke() + onMenu        │
│  app.js  the editor (one closure)             │        └────────────┬─────────────┘
│    doc model, masks, layers, selection, undo  │                     │ ipcRenderer.invoke
│    tools, pointer handling, panels, dialogs   │                     ▼
│    render loop, PNG/JPG/SVG, PDF and print    │        ┌──────────────────────────┐
│    generators, linked maps, autosave          │ ◀───── │ main.js (Node.js)        │
│    COMMANDS table, shortcuts, test runner     │  menu  │ windows and app menu     │
└───────────────────────────────────────────────┘ cmds   │ open/save/export dialogs │
                                                         │ reads .mapp, assets,     │
                                                         │ fonts; PDF and print;    │
                                                         │ autosave; guide window;  │
                                                         │ test hooks (MAPP_TEST)   │
                                                         └──────────────────────────┘
```

The window runs with `contextIsolation: true`, `nodeIntegration: false` and `sandbox: true`, and `index.html` sets a Content-Security-Policy that allows only local scripts. Keep it that way: add a new disk or OS feature as an IPC handler in `main.js` and a one-line wrapper in `preload.js`, never by loosening these settings.

### IPC handlers in main.js

| Channel | `window.api` call | What it does |
| --- | --- | --- |
| `save-project` | `saveProject(data, path)` | Writes a `.mapp`; shows Save As when no path |
| `open-project` | `openProject()` | Open dialog, returns `{ filePath, data }` |
| `export-image` | `exportImage(bytes, ext)` | Save dialog for PNG, JPG or SVG bytes |
| `export-pdf` | `exportPdf(bytes, page, name)` | Lays the PNG on a page in a hidden window, `printToPDF`, saves |
| `print-map` | `printMap(bytes, page)` | Same page, sent to the system print dialog |
| `pick-map` | `pickMap(base)` | Chooses a map to link; returns absolute and relative paths |
| `read-map` | `readMap(link, base)` | Opens a linked map, trying the relative path first |
| `read-assets` | `readAssets(style, keys)` | Returns asset SVG text, for SVG export |
| `read-font` | `readFont(file)` | Returns a font as base64, for SVG export |
| `import-assets` | `importAssets()` | Picks the user's own images to add as assets |
| `autosave-write` · `-read` · `-clear` | `autosaveWrite` etc. | One backup file, `userData/autosave.mapp` |
| `open-guide` | `openGuide()` | Opens the user guide window |
| `native-edit` | `nativeEdit(cmd)` | Cut, copy and paste inside text fields |
| `confirm` | `confirm(...)` | Native yes/no box |
| `test-capture` · `test-write` | `testCapture`, `testWrite` | Test mode only: screenshot and write files |

Handlers that take paths or names validate them (for example `read-assets` only accepts `[a-z0-9-]` keys) so the page can't read arbitrary files.

Menu items in `main.js` send a command name on the `menu` channel. The page looks it up in the `COMMANDS` table in `app.js` (`api.onMenu(cmd => COMMANDS[cmd]?.())`), and top bar buttons use the same table through `data-cmd` attributes, so a new command only has to be added once.

## 5. The editor (app.js)

`app.js` is one IIFE closure. Its state lives in a handful of variables: `doc` (the map), the masks, `selection`, `ui` (tool settings), `view` (zoom and pan) and the undo `history`. Functions are grouped by banner comments (`// ---- realms`, `// ---- lighting` and so on), so search for a banner to find a feature.

### The document

`makeDoc()` creates the map object that is saved to disk. Everything that should be saved must live in `doc`.

| Field | Holds |
| --- | --- |
| `app`, `version` | `'Pocket-Mapp-Creator'`, `1` — checked when a file is opened |
| `name`, `type`, `style`, `seed` | Map name; `world` · `town` · `battle`; one of the five styles; land seed |
| `width`, `height` | Map size in map pixels |
| `grid`, `border`, `look`, `coast` | Grid settings; border on or off; whole-map filters and vignette; coastline overrides |
| `layers` | `water`, `land`, `assets`, `text`: each `{ visible, locked, fx? }`; `fx` = layer opacity, shadow, glow |
| `dungeon` | `{ size, cells: ['x,y', …], fill, wall, wallW, v }` or `null` |
| `scale`, `light` | Measure tool scale; lighting on, darkness, night colour |
| `objects` | Everything placed on the map, in drawing order (below) |
| `custom` | The user's imported images, as data URLs |

Land, ground paint and texture paint are not objects. They are canvases ("masks") drawn at `maskScale` (about 3.2 million pixels whatever the map size): `landMask`, `pathMask` and one alpha mask per texture in `texMasks`.

### Objects

Every object has an `id` (from `uid()`), a type `t`, and usually `x`, `y` (centre), `s` (scale), `r` (degrees), `o` (opacity), `hidden`, `locked`, and optional effects `ef`.

| `t` | Extra fields | Layer |
| --- | --- | --- |
| `asset` | `a` (asset id or `custom:<id>`), `fx` (flip), `light`, `link` | Assets |
| `line` | `kind` (river, road, trail, border, wall, ink, realm), `w`, `pts` (absolute points); realms add `name`, `color`, `fill`, `clip`, `labelId` | Assets |
| `shape` | `kind` (rect, ellipse, poly), `w`, `h`, `pts` (relative to the centre), `fill`, `wall`, `wallW` | Assets |
| `text` | `text`, `font`, `size`, `color`, `bold`, `italic`, `spacing`, `curve`, `halo`, `noIndex`, `realmOf` | Text |
| `legend` | `title`, `size`, `font`, `realms`, `places` | Text |

`layerOf(o)` says which layer an object is on. `insertObj(o)` keeps the order realms → shapes → everything else, so rooms and realms always sit under the icons; `insertLow(o)` puts generated rivers and roads under the icons too.

### Drawing a frame

`loop()` runs on `requestAnimationFrame` and calls `draw()` only when `needsDraw` is true, so set `needsDraw = true` after any visible change. `renderMapContent(ctx, base)` draws a whole map onto any canvas and is shared by the screen, PNG/JPG export, PDF and print:

1. `base`: sea, land, coast and paper, made by `MT.renderBase()` and cached until `baseDirty` (rebuilt by `rebuildBase()`)
2. Texture paint (`texComp`)
3. Grid
4. Assets layer through `drawLayer()` (layer effects): the dungeon floor plan, then each object
5. Lighting, then the border
6. Text layer through `drawLayer()`
7. Vignette; the whole-map filters are a CSS filter on the stage and `ctx.filter` on export

On screen, `draw()` then adds selection boxes, handles, brush cursors, tool previews, the measuring line and link badges, which never appear in exports.

### Tools and input

`setTool(name)` switches tool, picks the matching layer and calls `renderToolOptions()` to fill the bar above the map. Pointer events on the stage go to one `pointerdown` handler that branches on `tool`, stores a `dragState`, and lets `pointermove` and `finishPointer()` continue it. Keys are mapped in the `keydown` handler; `typingNow()` stops shortcuts while a text field has focus.

### Panels

`renderProps()` builds the Properties panel as HTML for the current selection (or the map when nothing is selected) and wires inputs with `live('#id', 'field')`. `renderUsed()` builds the Assets used list and `renderLayers()` the Layers panel; `refreshPanels()` redraws all three.

### Undo, save and autosave

`commit()` takes a `snapshot()` (JSON of `doc` plus the masks as ImageData, de-duplicated) and pushes it to `history`, keeping 60 steps; `undo()` and `redo()` call `restore()`. Call `commit()` once at the end of every user action, not during a drag.

`serialize()` writes `doc` plus the masks as PNG data URLs; `deserialize()` checks `app`, merges the file over `makeDoc()` so older files get new fields' defaults, and reloads the masks. When you add a field to `doc`, give it a default in `makeDoc()` and older maps keep opening. Autosave writes the same JSON every 60 seconds while there are unsaved changes.

## 6. Terrain, textures and generators

These three files are pure helpers on `window.MT`: they take canvases, numbers and seeds and return canvases or plain data. They know nothing about `doc`, so they are easy to test and reuse.

### terrain.js

`MT.renderBase(opts)` turns the land and ground masks into the finished sea-and-land picture: distance transforms from the coast (`MT.distance`) drive the coastline ink, the ripple rings, shallows and beaches, then paper grain, stains and the style's vignette go on top. Each style's look is one entry in the `LOOK` table (colours, coast width, number and spacing of rings, grain); the Coastline & colours settings override it through `opts.coast`. `PAPER_RGB` holds each style's paper colour for areas with no land.

`MT.generateLand(mask, seed, coverage, { scale, fall })` paints random land from layered value noise (`MT.valueNoise`): `scale` sets the size of features and `fall` how strongly land fades towards the edges (continent 3.2 / 0.55, islands 5.5 / 0.35, archipelago 9 / 0.12). `MT.rng(seed)` is the seeded random number generator used everywhere a result must repeat.

### textures.js

`MT.TEXTURES` lists the 12 textures (stone, cobbles, wood, dirt, grass, sand, rock, snow, water, marsh, jungle, lava). `MT.textureTile(type, style)` draws a seamless 128 px tile from three colours per style and caches it. Copperplate and Night & Gold have no colours of their own: `derive()` works them out from the parchment colours. The texture brush, room floors and the dungeon floor all fill with patterns made from these tiles.

### generate.js

| Function | Returns |
| --- | --- |
| `MT.nameGen(rng)` | Name makers: `town()`, `realm()`, `sea()`, `mountains()`, `forest()`, `land()`; never repeats a name in one map |
| `MT.voronoiCells(sites, W, H, seed, rough)` | One polygon per site covering the map; shared edges roughened identically on both sides |
| `MT.astar(cost, gw, gh, start, end)` | Grid path avoiding `Infinity` cells, or `null` |
| `MT.smoothLine(pts, iters)` | Chaikin-smoothed polyline |
| `MT.dungeonLayout(cols, rows, opts, rng)` | `{ rooms, cells, doors, roomOf }` on the grid |
| `MT.townLayout(W, H, opts, rng)` | `{ square, streets, lots, bsize, centre }` |

The app side of the generators lives in `app.js` under the banner `random maps`: `generateWorld()`, `generateTown()`, `generateDungeon()` turn these layouts into real objects with `addAsset()`, `addText()`, `insertLow()` and `finishRealm()`, and `routeRoad()` builds the cost grid from the land mask and mountain assets for `MT.astar`. `runGenerator(tab, opts)` wraps them so one generation is one undo step. The same seed and options always give the same map, so never call `Math.random()` inside a generator: use the `R` passed down from `MT.rng(seed)`.

## 7. Assets

Every built-in asset is drawn by code in `tools/generate-assets.js`, once per style, so no drawing is ever copied from elsewhere and all 785 SVGs are CC0. Never edit the SVGs or `src/asset-manifest.js` by hand: change the generator and run `npm run assets`.

### How an asset is defined

```js
add('secret-door', 'Secret Door', 'fantasy', 'battle', (k) => {
  const { c } = k;
  let s = k.rect(4, 48, 120, 32, c.stone);
  s += k.rect(40, 50, 48, 28, 'none', { w: 0.6 });
  return s;
}, 128, 128);
```

`add(id, name, genre, kind, draw, w, h)` registers one asset. `genre` is `fantasy`, `scifi`, `modern` or `realistic`; `kind` is `world` (side view for world maps), `town` (3/4 view), `battle` (top-down) or `decor` (compass, cartouche, scale bar). `draw(k)` returns SVG markup for a `w` × `h` box using the drawing kit `k`:

| Helper | Draws |
| --- | --- |
| `k.c` | The style's palette: `ink`, `paper`, `stone`, `roof`, `wood`, `leaf`, `water`, `metal`, `glow`, `accent` and more |
| `k.poly`, `k.line` | Closed shape, open line (points as `[[x, y], …]`) |
| `k.rect`, `k.circ`, `k.ell` | Rectangle, circle, ellipse |
| `k.srect`, `k.scirc` | Straight-edged versions with no wobble, for sci-fi and modern pieces |
| `k.fillOnly` | A filled shape with no outline |
| `k.hatch`, `k.stipple` | Shading lines and dots (only drawn in styles with `hatch: true`) |

Use palette names, never fixed colours, so the asset redraws correctly in every style. `poly`, `line`, `rect`, `circ` and `ell` add the style's ink outline and a hand-drawn wobble by themselves.

### Styles

The `STYLES` table at the top of the generator defines each style: `label`, stroke width `sw`, `hatch` (shading on or off), `wash` (the watercolour filter pass) and the palette `c`. The generator writes `assets/<style>/<id>.svg` for every asset and style, then the manifest with each asset's id, name, genre, kind and padded size.

In the app, `assetInfo(id)` reads the manifest, and `KIND_BASE` (`world` 0.8, `town` 1, `battle` 0.55, `decor` 1.2) sets each kind's starting scale, so an asset's on-map size is `w × base × s`.

### Adding an asset

1. Add an `add(...)` call in the right group in `tools/generate-assets.js`.
2. Run `npm run assets` and check the output line (it prints the asset and file count).
3. Run the app and find it in the library under its genre and kind.
4. Update the asset count in `README.md`, `docs/USER-GUIDE.md` and the table in `ASSET-LICENSES.md`.

## 8. How-tos

Each recipe lists every place that needs a change. Search `app.js` for the names in `code` to find the spot.

### Add a tool

1. Add a button to `#tools` in `src/index.html`: `<button class="tool" data-tool="mytool" title="… (K)"><span>✦</span>Name</button>`.
2. In `setTool()`, add the tool to the `want` table so it switches to the right layer.
3. Add its key to the `map` table in the `keydown` handler, after checking the letter is free.
4. In the `pointerdown` handler, add a branch for `tool === 'mytool'` that sets a `dragState`; continue it in `pointermove` and end it in `finishPointer()`, calling `commit()` once.
5. Add a branch in `renderToolOptions()` for its settings bar, keeping settings in `ui`.
6. Set its cursor in the cursor block of `pointermove`, and draw any preview in `draw()`.
7. Add it to the shortcuts list in `shortcutsDialog()`, the user guide and the README.

### Add an object type

1. Give it a new `t` and draw it in `drawObject()`; return its size from `objSize()` so selection boxes and handles work.
2. If it is not on the Assets layer, return its layer from `layerOf()`.
3. If clicks should not use its bounding box, add a case to `hitObj()`.
4. Add its Properties in `renderProps()` and its row name in `renderUsed()`.
5. Draw it in `buildSvg()` too, or it will be missing from SVG exports.
6. Any new top-level setting goes in `makeDoc()` with a default.

### Add a texture

Add an entry to `TEX` in `textures.js` (label plus base, dark and light colours for parchment, colour and watercolour) and a `case` in `textureTile()` that draws its pattern. It then appears in the texture brush, room floors, dungeon floors and the random dungeon dialog.

### Add a map style

1. Add the style to `STYLES` in `tools/generate-assets.js` and run `npm run assets`.
2. Add an entry to `LOOK` and `PAPER_RGB` in `terrain.js`.
3. Add it to `INK`, `PAPER`, `WALL_COL` and `STYLE_DESC` in `app.js`, the border colours in `lineColours()`, and `INKS` in `textures.js`.
4. Add an `<option>` to the Style menu in `index.html` and a `.asset.style-<name>` background in `styles.css`.
5. Check a world, a town and a dungeon in the new style, then update the style counts in the README, the user guide and `ASSET-LICENSES.md`.

### Add an export format

Render with `renderExportCanvas(scale, grid)` (it uses `renderMapContent()`, so the export matches the screen) or build text the way `buildSvg()` does. Send the bytes to `main.js`: reuse `exportImage(bytes, ext)` for a plain file, or add a handler for anything that needs the main process, then add a command to `COMMANDS` and a menu item.

## 9. Testing

The app has a built-in test runner that drives the real editor in a hidden display and writes screenshots. It runs on Linux with `xvfb-run` (install the `xvfb` package); on Windows and macOS, run it in WSL or a Linux VM.

| Command | Runs |
| --- | --- |
| `MAPP_TEST=out xvfb-run -a -s "-screen 0 1600x1000x24" npx electron --no-sandbox .` | The full test, `runTest()` in `app.js` |
| `MAPP_TEST=out MAPP_QUICK=gen xvfb-run -a … npx electron --no-sandbox .` | One quick scenario from the `QUICK` table |

When the test finishes it sets the window title to `TESTDONE …` with its results, `main.js` prints that line and quits, and screenshots and exports land in the `out` folder. Run it with `timeout 500` in front so a hang can't block you.

### What the full test checks

The full test builds maps of every type and style and checks, among other things: land and ocean brushes, the fill bucket (gap closing and leak refusal), landmass select-scale-undo, layers and locking, stamping, rotating, copy and paste, text, shapes, textures, effects, snap, 8K export, map look filters, save and reload, and undo/redo. A line such as `undo=true redo=true reload=true shapes=5` means each check passed; compare it with the previous run. Counts that depend on random scatter (for example `items=` in the landmass check) can change from run to run.

### Quick scenarios

| `MAPP_QUICK` | Checks |
| --- | --- |
| `styles` | Copperplate and Night & Gold, on screen and exported |
| `gen` | Random world, archipelago, 3/4 town, top-down town and dungeon, lit and dark |
| `features` | Realms, auto-routed road, map key, measure, layer effects, lighting, SVG, PDF, reload, dungeon undo |
| `svg` | Builds an SVG, renders it back to PNG and writes a reference PNG to compare |
| `links` | Linked map opens, Back returns, link kept |

To add a check, add a function to `QUICK` (`QUICK.myname = async (dir) => { …; return 'summary'; }`) and use `qshot(dir, name)` for screenshots. Always look at the screenshots after a visual change; the numbers alone don't show a drawing that looks wrong.

Before every release, also run the app by hand: create one map of each type, save, close, reopen, and export PNG, SVG and PDF.

## 10. Building and releasing

Installers are built by `.github/workflows/build.yml` on GitHub's Windows, macOS and Ubuntu 24.04 runners with Node.js 24, and uploaded to a GitHub Release with the `gh` tool. The workflow never creates workflow artifacts, so it uses none of the account's artifact storage.

| How it starts | Where the installers go |
| --- | --- |
| Actions → Build installers → Run workflow | A draft release `build-<run number>`, visible only to repository owners; delete it when done |
| Pushing a tag such as `v0.3.0` | A draft release named after the tag, made public once all three builds succeed |

| Runner | Files |
| --- | --- |
| Windows | `*-win-x64.exe` (installer), `*-win-portable.exe` |
| macOS | `*.dmg` (unsigned: users right-click → Open the first time) |
| Linux | `*.AppImage`, `*.deb` |

The workflow runs four jobs: `prepare` creates the draft release, the three `build` jobs run `npm ci` then `npm run dist:<os>` and upload their files, and `publish` makes a tagged release public. Each `dist` script runs `npm run guide` first and passes `--publish never`, so electron-builder never uploads anything itself. electron-builder's settings live under `build` in `package.json` (app id `com.pocketdesigns.pocketmappcreator`, icons in `build/`, the `files` list that goes into the app).

### Releasing a new version

1. Update the version everywhere listed in section 12, then run `npm install` so `package-lock.json` matches.
2. Update anything new in the README and the user guide, and run `npm run guide`.
3. Run the full test (section 9) and check the screenshots.
4. Commit and push, then tag: `git tag v0.4.0` and `git push origin v0.4.0`.
5. Wait for the workflow, then check the release page lists all five installer files.

If a build fails because `package-lock.json` is missing or out of date, run `npm install` locally and commit the lockfile: `npm ci` refuses to run without a matching one.

## 11. Docs, licences and conventions

### Keeping the docs in step

Any change people can see goes into `docs/USER-GUIDE.md`; run `npm run guide` to rebuild the in-app guide (`tools/build-guide.js` uses `marked`, adds anchors and copies `docs/guide-images/`). The shared Claude Doc copies of the user guide and this developer guide should be updated to match. New features also go in the README feature list, and new shortcuts in `shortcutsDialog()`.

Never add a third-party image, icon or font without checking its licence allows redistribution, and record it in `ASSET-LICENSES.md`. Keep the MJO-Art icon credit wherever the icon is mentioned.

### Code conventions

- Plain modern JavaScript, no framework, no bundler; the renderer can't use `require`.
- Every source file starts with a header naming the app and "Copyright (c) 2026 Pocket-Designs — MIT Licence".
- Two-space indent, single quotes, semicolons; long one-line functions are fine where the existing code uses them.
- Comments explain why, in plain English (UK spelling in the UI: colour, centre).
- Map coordinates are in map pixels; convert screen positions with `toMap(e)`. Masks are at `maskScale`.
- Anything random in a generator uses the seeded `R`, not `Math.random()`.
- New saved settings get a default in `makeDoc()`; never rename or remove a saved field without handling older files in `deserialize()`.
- Every user action ends with one `commit()`; every visible change sets `needsDraw = true`.
- Disk and OS access only through an IPC handler in `main.js` with validated inputs.

## 12. Where the version numbers live

The app version is **0.3.0**. `package.json` is the one that counts: electron-builder puts it in the installer file names (`Pocket-Mapp-Creator-0.3.0-…`) and Electron reports it as the app version. Change these together for each release:

| File | Line | What it says | Change on release? |
| --- | --- | --- | --- |
| `package.json` | 4 | `"version": "0.3.0"` | Yes: the master version |
| `package-lock.json` | 3 and 9 | `"version": "0.3.0"` (top level and `packages[""]`) | Yes: run `npm install` after editing `package.json` and it updates itself |
| `docs/USER-GUIDE.md` | 3 | `Version 0.3` | Yes, then `npm run guide` |
| `src/guide/index.html` | 35 | `Version 0.3` | Rebuilt from the user guide by `npm run guide`; don't edit by hand |
| `docs/DEVELOPER-GUIDE.md` | top line, section 1 | `Version 0.3.0`, "Pocket-Mapp-Creator 0.3.0" | Yes |
| Git tag | — | `v0.3.0` | Yes: the tag you push starts the release build |
| `README.md` | 78–79 | `git tag v0.3.0` example | Optional: example only |
| `.github/workflows/build.yml` | 8–9 | `v0.3.0` in the how-to comment | Optional: example only |

Other version numbers that are **not** the app version:

| File | What it is | Change it when |
| --- | --- | --- |
| `src/js/app.js`, `makeDoc()` | `version: 1` — the `.mapp` file format version | Only if the save format changes in a way older versions of the app can't read |
| `.nvmrc` and `build.yml` (`NODE_VERSION: '24'`) | Node.js version for development and the build | Moving to a newer Node.js |
| `.github/workflows/build.yml` | `actions/checkout@v5`, `actions/setup-node@v5`, `ubuntu-24.04` | GitHub retires a version |
| `package.json` devDependencies | `electron ^44.7.2`, `electron-builder ^26.15.3`, `marked ^18.1.2` | Upgrading a tool; then commit the new `package-lock.json` |
